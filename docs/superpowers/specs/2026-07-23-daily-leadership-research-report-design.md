# A股市场研究日报设计

## 1. 目标与边界

在每日自动数据更新完成后，汇总市场、行业、消息、个股观察和历史兑现数据，生成一篇面向领导阅读的专业研究日报。

报告同时服务两个目标：

- 说清当前市场环境、主要方向、风险和需要验证的问题。
- 客观回顾近期观察样本的兑现情况，判断近期结果是否改善或走弱。

报告只做研究整理，不生成买卖、仓位、目标价或自动交易指令。软件变更、代码、研发过程和未上线实验不进入报告。

## 2. 设计原则

- **事实先于文章**：先构建带日期、来源和完整性状态的事实快照，再进行综合判断和文字润色。
- **高信息密度**：每句话应包含数字、事实、比较、因果判断或验证条件，不解释常识，不用套话填充篇幅。
- **口语但专业**：按“研究员给领导写晨报”的语气成文，结论先行，证据紧跟，避免机器式枚举和 AI 套话。
- **结论可追溯**：对外文章不暴露内部实现，但内部必须能将每个数字、实体和判断追溯到快照事实。
- **空结果也是结果**：没有新增观察标的是正常情况，不得为了凑内容提高其他线索的级别。
- **只发布可信成品**：数据、事实、脱敏或文字质量检查失败时，不发布半成品或机械模板。

## 3. 总体架构

```text
正式生产数据
  ├─ 市场环境与情绪
  ├─ 行业雷达与消息事件
  ├─ 短周期与中期观察
  ├─ 龙头观察与市场雷达个股
  └─ 历史成熟结果
           ↓
DailyReportFactsBuilder
  ├─ 日期对齐与新鲜度检查
  ├─ 实体归一化与跨来源去重
  ├─ 共振、冲突与证据缺口计算
  └─ 成熟样本统计
           ↓
内部事实快照（不对外展示）
           ↓
DailyResearchWriter
  ├─ 研究判断底稿
  └─ 领导版压缩与润色
           ↓
ReportValidator
  ├─ 事实校验
  ├─ 脱敏校验
  └─ 文字质量校验
           ↓
日报档案库 + 网页文章
```

各组件只承担一项职责：事实构建器不写文章，写作器不读原始日志或数据库，校验器不修改研究结论，档案库只保存通过校验的版本。

## 4. 正式输入能力

### 4.1 市场环境

- 大盘风险、市场风格、周线宏观趋势和市场阶段。
- 指数表现、成交变化、涨跌分布、涨跌停数量、行业 MA10 覆盖和市场情绪。
- 市场阶段的变化、快速翻转证据及证据强度。

### 4.2 行业、题材与消息

- 健康主线、低位启动、趋势延续、弱修复、过热高潮和退潮行业。
- 行业相对收益、成交承接、资金流和个股扩散程度。
- 经过时效检查的新闻、事件等级、来源质量、行业映射、概念热度和验证点。
- 消息、行业趋势和个股行为的一致、分裂或冲突。

### 4.3 个股观察来源

每日可用个股集合是以下正式观察来源的并集：

- 短周期正式观察。
- 短周期辅助观察。
- 中期 Watch 与 Elite 观察。
- 市场雷达个股。
- 龙头“优先观察”和“谨慎观察”个股。

龙头隐藏风险样本不进入正面观察名单，仅可成为风险背景。`research/` 下的搜索结果、实验候选和未上线策略均不进入日报。

同一只股票跨来源出现时只保留一个观察对象，内部保留所有来源、各自原始分数和证据，不将不同口径的分数混成一个伪综合分。

### 4.4 历史兑现与生命周期

- 短周期成熟样本的5日收益、MFE、MAE、目标触及率和机会风险比。
- 中期样本的10/40/80日收益、MFE、MAE、胜率和跑赢比例。
- 中期观察对象的新进、延续、升级、降级和移出事件。

未走完观察窗口的样本不进入胜率和平均收益统计。样本数不足时只陈述当前结果，不做趋势性判断。

### 4.5 数据状态

- 有效交易日、各来源数据日期、数据与消息截止时间。
- 当日扫描是否已完成、数据是否错位、历史结果是否已成熟。
- 可选来源是否缺失、过期或沿用旧缓存。

## 5. 空结果与运行状态

短周期和中期观察每日独立区分四种状态：

1. 已运行且有观察标的。
2. 已运行但没有标的通过规则。
3. 当前市场条件不满足，因而未触发。
4. 数据缺失或任务失败。

前三种属于正常研究结果，第四种才是异常。其他来源的个股不得填补为正式短周期或中期结果。如果只有雷达或龙头线索，对外文章必须将其写成独立观察，不得暗示其已通过正式筛选。

## 6. 事实快照设计

快照使用结构化 JSON，包含以下顶层区域：

```json
{
  "report_date": "YYYYMMDD",
  "generated_for": "latest_effective_trade_date",
  "cutoffs": {},
  "completeness": {},
  "market": {},
  "sectors": {},
  "events": {},
  "observations": [],
  "observation_source_status": {},
  "performance": {},
  "risks": [],
  "evidence_index": {}
}
```

`observations` 中的每个对象至少包含股票身份、内部来源集合、各来源原始证据、共振、冲突、证据缺口、风险、验证条件和失效条件。`evidence_index` 为每个可引用事实分配稳定标识，供生成后校验。

`report_date` 是东八区的报告发布日，`generated_for` 是报告使用的最近有效交易日。二者必须分开存储和展示：例如7月23日凌晨生成的报告归档为7月23日，行情有效日可能是7月22日。周末和节假日仍按实际发布日归档，并在文章中准确标注行情和消息各自的截止时间。

快照输入计算规范化哈希。相同日期且输入指纹未变时，不重复调用写作服务。

## 7. 写作与去 AI 味

### 7.1 两阶段写作

第一阶段生成不对外展示的研究底稿，只回答：

- 哪些事实对当日判断最重要。
- 哪些来源互相印证或互相冲突。
- 哪些空结果对当日判断有意义。
- 哪些结论只能保持中或低置信度。

第二阶段将底稿压缩为连贯的中文研究文章。该阶段只能改变表达，不得新增事实、数字、股票、行业或事件。

### 7.2 文风约束

- 结论先行，证据紧跟；能用数字说清时不使用空泛形容词。
- 正文使用自然段，不按数据字段逐项念出。
- 不使用“作为 AI”、“根据输入 JSON”、“综合来看”、“值得注意的是”、“需要指出的是”等机器或模板表达。
- 不为达到固定字数而扩写；长度由当日有效信息量决定。
- 没有清晰结论时直接写“暂时看不清”，并说明缺少的证据。
- 个股只选择存在明显共振、冲突或代表性的少量样本；每只同时说明依据、分歧、风险和下一步验证点。

## 8. 对外脱敏

领导版不得暴露：

- 软件名称、AI、Agent、模型、数据库、缓存、接口和自动任务。
- 内部策略名称、版本号、profile、状态枚举、参数、权重和阈值。
- 原始分数、详细过滤条件和可以反推核心选股方法的描述。
- 运行日志、调用状态和技术异常细节。

对外只使用“短周期观察”、“中期观察”、“行业强度”、“个股活跃度”、“综合研判”等业务表达。一切内部映射在事实快照和校验记录中保留，不进入可搜索的领导版正文。

## 9. 报告成品

### 9.1 标题

每篇报告拥有独立标题，由当日核心矛盾生成，长度原则上为12至24个中文字符。标题不重复日期，不使用“重磅”、“爆发”、“必看”等营销词，不得超出正文证据强度。

示例：

- 缩量分化延续，强势方向仍待扩散
- 市场风险回落，主线共振有所增强

### 9.2 正文结构

报告是一篇连续阅读的文章，不做复杂卡片或看板。正文使用五个简洁的内容区域：

1. **核心判断**：用一段话说清市场强弱、主线清晰度、机会质量和置信度。
2. **市场脉络**：交代指数、成交、市场宽度、行业扩散和重要消息之间的关系。
3. **重点方向与个股**：只保留有代表性的行业和股票，说明依据、分歧和验证点。
4. **近期表现与风险**：基于成熟样本说明近期观察质量，并列出主要风险。
5. **今日观察点**：提出下一交易日最值得验证的2至4个问题。

正文长度由当日信息量决定，不设最低字数。页面底部只保留：

> 本文基于公开市场数据进行研究整理，仅供内部研究参考。

## 10. 档案与检索

### 10.1 存储模型

使用本地 SQLite 保存报告，不增加外部服务。存储分为两层：

- `daily_reports`：每个报告日期的当前正式版本，供网页和搜索读取。
- `daily_report_versions`：保存每次生成与修订，供内部追溯。

正式记录至少包含：报告发布日、有效交易日、标题、数据截止时间、消息截止时间、纯文本正文、结构化正文、检索关键词、输入指纹、生成时间、修订时间和发布状态。每个报告发布日只有一份当前正式版本。

### 10.2 检索能力

- 单日和日期区间查询。
- 标题和全文关键词查询。
- 股票名称、股票代码、行业、题材、事件和风险词查询。
- 日期与关键词组合查询。

优先使用 SQLite FTS5 对当前正式版本建立全文索引；运行环境不支持 FTS5 时降级为参数化 `LIKE` 查询。搜索结果只显示日期、标题和命中摘要，点击后进入完整文章。

### 10.3 网页路由

- `/reports`：日期和关键词查询入口。
- `/reports/{report_date}`：某日完整报告。

文章页顶部保留“上一日 / 下一日”切换，不增加卡片看板、分页正文或复杂交互。

## 11. 自动生成和重试

### 11.1 凌晨2:00首次生成

当前 `daily_web_update.py --mode full` 的正式日报步骤必须调整到全量链路最后，使其在以下步骤全部完成后执行：

- 行情下载与历史库同步。
- 当日短周期和中期扫描落库。
- 市场上下文、新闻和概念更新。
- 龙头观察池刷新。
- 市场雷达快照刷新。
- 短周期成熟结果回填。
- 中期历史质量审计和导入。

报告发布日是凌晨任务触发时的东八区日期，行情对象是最近有效交易日。报告单独标记行情、数据和消息的截止时间。

### 11.2 早晨8:30自动补救

早晨8:30市场雷达扫描完成后，执行当日报告状态检查：

- 2:00已成功发布：直接跳过，不重复调用写作服务。
- 2:00失败、缺失或生成结果未通过校验：使用8:30刷新后的事实重新生成。
- 8:30重试成功：发布为当日正式报告，消息截止时间记录为8:30实际刷新时间。
- 两次都失败：保留上一份有效报告，并显示其真实日期，不发布低质量替代品。

生成流程使用报告日期、输入指纹和任务锁保证幂等，防止凌晨和早晨任务重复生成或并发覆盖。

## 12. 发布校验与容错

### 12.1 数据校验

- 行情有效日、观察来源和历史结果的日期对齐。
- 短周期或中期结果为空时，仍能找到当日扫描或未触发的可验证状态。
- 新闻、雷达、龙头等非核心来源缺失时，不将缺数据解释为无机会；必要时降低置信度或省略对应结论。
- 核心行情或当日正式扫描状态缺失时不发布当日报告。

### 12.2 事实校验

- 正文中的日期、数字、股票、行业和事件必须存在于事实快照。
- 同一股票不得跨来源重复计数。
- 不同口径的原始分数不得直接比较或混合。
- 未成熟样本不得进入收益统计。
- 个股必须来自第4.3节的允许集合。

### 12.3 脱敏校验

使用禁止词、内部标识正则和业务语义检查组合扫描标题、正文、关键词和搜索摘要。任何内部策略名、版本号、参数、原始评分或技术实现进入对外文本时，该版本不得发布。

### 12.4 文字质量校验

- 去除重复结论、模板过渡语和无事实支撑的形容词。
- 标题与当日核心证据相符。
- 每个重点个股同时存在依据和风险或分歧。
- 不包含买入、卖出、仓位、目标价和收益承诺。

## 13. 测试与验收

### 13.1 事实构建测试

- 短周期为空、中期为空和两者同时为空。
- 中期观察因市场条件未触发。
- 只有雷达或只有龙头个股线索。
- 同一股票出现于多个来源。
- 不同来源对同一股票存在冲突。
- 新闻过期、来源沿用、数据日期错位和历史样本未成熟。

### 13.2 生成与校验测试

- 写作返回不合法结构、空文章或重复套话。
- 文章虚构数字、股票、行业或事件。
- 内部策略名、版本、枚举、参数或技术字段泄漏。
- 标题夸大、正文结论与标题不一致。
- 个股只有正面描述而没有风险或验证条件。

### 13.3 存储与搜索测试

- 按标题、正文、股票名称、股票代码、行业和日期检索。
- 日期与关键词组合查询。
- FTS5可用和降级 `LIKE` 两种路径。
- 同日重跑产生修订版本，不丢失历史。
- 搜索只返回正式发布版本，不暴露内部快照和失败草稿。

### 13.4 调度与集成测试

- 全量更新中报告生成严格位于龙头、雷达、短周期成熟结果和中期审计之后。
- 2:00成功后8:30不重复生成。
- 2:00失败后8:30能自动补生成。
- 两次都失败时保留上一份有效报告和真实日期。
- 并发触发只能发布一份正式版本。

## 14. 完成标准

- 凌晨2:00全量更新后能生成当天的研究日报，并正确标记其使用的最近有效交易日。
- 2:00失败时，8:30扫描后能自动补生成，并在成功后仅发布一份正式版本。
- 日报覆盖正式市场、行业、消息、个股和历史兑现能力，不引入未上线研究结果。
- 短周期或中期无标的时，报告能准确表达状态，不用其他来源填补。
- 所有对外数字和实体均可追溯，不存在虚构事实。
- 对外文章不暴露软件、AI、内部策略、版本、参数、原始分数和过滤逻辑。
- 正文保持口语化、专业和高信息密度，不使用低信息量模板填充。
- 每日报告长期保存，可按日期、标题、全文、股票、行业和风险词查询。
