# 日报与市场专栏优化设计

日期：2026-09-14。依据：生产只读核查、当前代码与用户授权“列详细文档并按文档优化项目”。

## 目标与范围

让用户清楚知道数据是否及时、结论依据是什么、研究表现是否可用于当前判断。采用现有 Python / SQLite / Jinja 页面架构，修复链路与展示，不重写平台。

本轮包括：行情基础数据类型修复、日报发布校验、交易日时效门槛、历史表现口径、证据展示、旧报告提示、刷新状态、栏目分工与验证指引。HTTP 行情中转继续按用户确认的原配置使用。正式短线、长线参数保持当前配置；不通过降低门槛制造推荐。

## 设计决定

- 交易日依据缓存的 SSE 日历，不能以工作日猜测节假日。定时早报以报告日前最近已完成交易日为最低要求；更新任务使用既有收盘截止逻辑。不能验证日历时停止当日发布，明确原因。
- 保存数据的类型标准化限定于股票主数据，不对所有数值列全局转字符串。没有合法证券代码时不覆盖有效缓存。
- 发布校验使用现有确定性规则，修复畸形 JSON 崩溃边界；AI 模型品牌不是内容合格条件。
- 来源快照只保存允许公开的字段，外链仅接受 HTTP(S)，拒绝带凭据链接及脚本协议；不把内部原始对象或密钥送到前端。
- 历史回测字段仍可研究阅读，但不赋予新的有效性。未重跑结果不能宣称通过当前版本验证。
- 已发布文章保留历史版本。新增展示警示不改写旧正文；不得用当前数据回填旧文章依据。
- 已有数据时钟、历史导航和复盘模块保留，避免重复建设；本轮不自动生成“昨天判断正确”的无证据结论。

## 验收标准

1. 含数值 symbol、空值、退市股票和已有缓存混合类型的批量下载可正常保存，证券代码不丢零。
2. 9 月 14 日报告 + 9 月 4 日行情被阻止；周一早报使用上周五有效行情可通过；节假日遵守日历；日历缺失明确失败。
3. 无证据数字、未知证据、错误结构无法直接发布；修订通过可发布；不合格降级稿仍不可发布；失败不覆盖既有文章。
4. 新日报证据按段可查看，旧日报显示证据快照缺失；危险 URL 不渲染成链接。
5. 历史绩效显示回测来源与样本范围，不能呈现为真实当日荐股成绩。
6. 更新完成但行情未到目标日不会被报告为数据已更新成功。
7. 针对性测试、全套回归及真实浏览器阅读/展开操作通过；记录未执行的生产补数和多年回测，不混为已完成。

## 上线与回退

先本地验证并提交可审查变更，再按现有部署流程发布。生产数据补齐是独立运行验收：至少确认股票主数据保存、核心日行情推进、选股快照推进、日报发布及雷达时效。任何没有实际执行的步骤必须标记未完成。出现问题可回退代码版本，保留新增公开证据字段的向后兼容性；不删除生产数据库或历史缓存。
