# 短线/长线历史价格列实施计划

**目标：** 在短线历史信号和长线历史记录中统一展示“基准买入价”与“最新价/浮盈亏”，采用 T+1 开盘价作为首选基准，并保持页面紧凑、清晰。

**约束：** 不修改量化评分、历史收益结果或数据库结构；行情读取必须批量完成，禁止逐股请求外部接口。

## 任务 1：批量生成历史价格上下文

**文件：**
- 新建：`web_app/services/history_price_service.py`
- 修改：`web_app/services/signal_service.py`

**步骤：**
1. 新增批量行情补充函数，接收记录列表、历史库路径和信号日期字段。
2. 一次查询涉及股票在最早信号日前后至最新交易日的 `stock_daily` 行情。
3. 对每条记录计算并附加：T+1 开盘基准价、缺失时的推荐日收盘回退价、最新收盘价、最新交易日、当前浮盈亏和颜色语义。
4. 在短线历史信号查询与长线审计样本查询返回前调用同一函数，保证两页口径一致。
5. 保留现有 5 日、10/40/80 日收益与生命周期字段，不覆盖任何既有结果。

## 任务 2：优化短线历史结果表

**文件：**
- 修改：`web_app/templates/signals.html`

**步骤：**
1. 在股票信息与收益结果之间加入“基准买入价”和“最新价 / 浮盈亏”两列。
2. 主行只显示价格，副行显示“T+1 开盘”或“推荐日收盘回退”；最新价副行显示交易日期与浮盈亏。
3. 缺失数据统一显示短横线和简短原因，不制造大块空白。
4. 调整空状态 `colspan`，保持筛选和分页行为不变。

## 任务 3：优化长线历史结果表

**文件：**
- 修改：`web_app/templates/longterm_pool.html`

**步骤：**
1. 使用与短线页相同的两列结构和文案口径。
2. 将价格列放在股票/入池日之后、80 日结果之前，阅读顺序为“何时入池 → 以什么价格观察 → 现在多少钱 → 阶段结果”。
3. 当前浮盈亏只作为实时观察信息，不替代 10/40/80 日既有复盘结果。
4. 调整空状态 `colspan`。

## 任务 4：统一视觉样式

**文件：**
- 修改：`web_app/static/styles.css`（若项目实际主样式文件名不同，以模板现有引用为准）

**步骤：**
1. 新增紧凑价格单元格样式：数字使用等宽数字、主次层级明确、正负收益沿用现有涨跌色。
2. 控制两列最小宽度与换行，桌面端不挤压关键结论，窄屏允许横向滚动。
3. 不增加卡片边框或额外背景块，避免表格视觉噪声。

**步骤：**
1. 通过项目既有 SSH 方式同步变更。
2. 重启 `stock-web` 服务使模板与后端逻辑生效。
3. 不执行测试或额外验证，除非用户另行授权。
