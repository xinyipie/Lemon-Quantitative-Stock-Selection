# 长线质量观察与趋势确认分层

## 背景与已确认事实

生产记录最后一次长线观察池非空为 2026-06-29（1只）。2026-07-23 至 09-04 的32份每日快照中，31份标记未触发长线扫描。旧页面还把普通观察股评分≥85误分为Elite，且把Elite空结果作为整个长线池的最近运行状态。

用户已同意调整、直接部署并扫描最新长线股。

## 实施口径

1. **质量观察**：`main.select_longterm_quality_pool`。使用完整交易日的流动性与风险事件候选，取消观察层单日资金流正值要求、换手与回调择时限制。继续批量请求，不逐股拉接口。
2. 财务边界沿用原生命周期分支：市值≥80亿元使用防御质量边界（ROE≥7%、利润同比≥0%、负债率≤65%、PB≤3.5、正PE≤55、PS≤4），30亿至80亿元使用弹性质量边界（ROE≥5%、利润同比≥0%、负债率≤75%、PB≤6.5、正PE≤120、PS≤8）。市值无上限；成交额仍至少2亿元。所有必需字段须为有限有效数值，估值须为正。
3. 防御质量观察依据公司市值和财务边界独立运行，不再依赖一个与v18前置条件互斥的市场分支。
4. **质量排序**：ROE分位40%、利润增速分位30%、PB/PE/PS逆向分位均值30%。只用于观察列表排序，无评分准入线，不解释为胜率或收益预测。属于新观察规则，尚未完成历史收益验证。
5. **趋势确认**：原 `longterm_quality_lifecycle_v18_market_sync` 保留市场同步门槛、个股择时、生命周期82分门槛及原Top3/行业约束。`run_daily_selection` 和回测仍使用原正式结果；新观察不会成为回测买入候选。
6. **展示与Elite**：先保留原压缩后的确认候选，再按质量排序补充至最多10只，同一行业最多2只。只有原确认候选经过原Elite条件才可提醒；质量分不能触发Elite。80天冷却继续作用于Elite。
7. **解释**：保存质量输入数、财务缺失、财务未达标、质量达标、确认数、展示数及Elite数。原规则实际执行时额外保存均线、动量、回调、行业、财务、支撑距离和评分前数量；未执行时记录市场原因。
8. **失败保护**：独立扫描失败保存错误，不清空旧池。页面显示失败与旧结果，区分扫描时间、行情日期。基础行情空、日期回退或财务全部缺失不发布空池。
9. **研究隔离**：新观察不进入原 `live_selections.csv` 的荐股样本；未确认观察不调用原长线买入区间AI模板。页面按明确profile区分Watch/Elite，不按高分猜测。

## 修改文件

- `main.py`：质量筛选、最新日期检查、长线正式过滤诊断、每日流程接入、观察与正式研究记录隔离。
- `longterm_live_pipeline.py`：并行质量观察列表与原确认/Elite列表组合。
- `longterm_scan.py`：独立扫描入口及SQLite扫描诊断；不写短线结果、不覆盖日报快照。
- `config.py`：质量观察展示上限10只。
- `daily_report/selection_snapshot.py`：按实际质量扫描状态保存结果，不再以熊市推断观察未扫描。
- `web_app/services/signal_service.py`：读取确认身份与质量解释、Watch/Elite按身份分类、当前股票去重。
- `web_app/app.py`、`templates/longterm_pool.html`：扫描漏斗、失败提示、确认状态及分数口径。
- `tests/test_longterm_quality_observation.py`：准入、数据缺失、分层、持久化、故障保留、页面与原规则过滤诊断回归。

## 运维与验证

服务器在项目目录加载现有环境后执行：

```bash
python longterm_scan.py
# 核验目标日期对应的最新完整交易日
python longterm_scan.py --target-date 20260914
```

当日18点前按已有系统口径使用前一交易日；历史目标及18点后要求覆盖目标日。运行前应完成行情/财务补数，运行时与既有更新任务使用同一互斥锁。

初轮全套回归：1050 passed、22 skipped、5 subtests passed。新增过滤诊断后的针对性回归已通过；最终验证及生产扫描结果在部署后追加。浏览器使用独立SQLite中的明确验收示例，未写入生产候选。

没有修改原行情服务地址、正式策略参数或交易执行功能。未重跑多年策略回测；质量观察并不意味着原策略已验证收益提高。
